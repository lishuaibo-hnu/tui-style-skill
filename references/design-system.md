# 终端设计参数与实现细节

本参考是可调整的设计起点。优先服从用户指定主题、现有应用约定、领域信息密度和实际终端能力。

## 1. 默认深色主题

| 角色 | 参考颜色 | xterm 256 色索引 | 使用位置 |
| --- | --- | --- | --- |
| 背景 | `#262626` | 235 | 应用底色 |
| 输入面 | `#303030` | 236 | 搜索、未聚焦输入框 |
| 主文字 | `#d0d0d0` | 252 | 内容 |
| 标题 | `#eeeeee` | 255 | 名称、重要值 |
| 辅助文字 | `#8a8a8a` | 245 | 系统、端口、时间和提示 |
| 边框 | `#4e4e4e` | 239 | 未聚焦分区 |
| 强调 | `#5fd7ff` | 81 | 当前分区、地址、重要操作 |
| 成功 | `#87d787` | 114 | 在线或成功 |
| 警告 | `#ffd75f` | 221 | 待核验、校验错误 |
| 失败 | `#ff5f5f` | 203 | 操作失败、错误 |
| 选中背景 | `#005f87` | 24 | 当前列表项 |
| 选中辅助文字 | `#87d7ff` | 117 | 当前行的次要信息 |
| 次要按钮背景 | `#005f5f` | 23 | 底部常用快捷键 |

主操作按钮可以使用强调色背景与深色文字。普通按钮应比主操作安静。状态同时显示符号和文字，例如 `● 在线`、`○ 离线`、`◌ 待核验`。

支持 16 色终端时映射为系统基础色；无颜色时用反显、指示符和文字保留焦点。不要用 `init_color()` 改写用户的全局调色板。浅色主题或已有主题优先沿用其语义颜色，不必强制深色。

## 2. 列表与详情布局

适用于资源管理的起点：

```text
  APPLICATION / 工作区                       连接状态  版本

  ╭────────────╮ ╭────────────╮ ╭────────────╮
  │ 主要概况   │ │ 状态概况   │ │ 常用概况   │
  ╰────────────╯ ╰────────────╯ ╰────────────╯

   1 全部    2 常用视图    3 收藏

  ╭─ 资源列表 ─────────────────╮ ╭─ 详情 ────────────╮
  │ / 名称、地址、备注搜索      │ │ 选中项名称         │
  │                            │ │ 状态与类型         │
  │ ▸ 当前资源         ● 状态  │ │                    │
  │   类型 · 地址 · 操作方式    │ │ 地址、配置、备注    │
  │                            │ │                    │
  │   其他资源         ○ 状态  │ │ [ Enter 主操作 ]   │
  ╰────────────────────────────╯ ╰────────────────────╯

   操作结果或提示                          最近更新时间
   Enter 操作    / 搜索    e 设置    ? 帮助    q 退出
```

对于中文资源管理器，可从 112 列开始使用左右分栏：列表约占可用宽度的 59%，余下给详情；小于该宽度改为上下排列。阈值需要按最长必需字段校验。

- 行高按可用高度选择：充足时“名称 + 辅助信息 + 留白”三行；中等时两行；紧凑时单行。
- 统计卡片不是必需组件。小窗口可以将其折叠为一行摘要。
- 宽窗口的详情可分为身份、地址、配置、记忆或说明、主操作；紧凑模式保留名称、关键参数和简短说明。
- 列表要显示滚动范围或其他滚动线索；超出列表的项目仍然可通过方向键找到。
- 不能只靠宽度断点：高度不足时也需减少分组和间距。

## 3. 文本、输入和焦点

框架的显示宽度和实际终端可能受组合字符、emoji 和东亚模糊宽字符设置影响。验证实际支持范围；简单 ASCII/中英文双宽测量不等于完整 grapheme 或 emoji 支持。

- 避免用 emoji 或 Nerd Font 图标承担核心信息；常见边框、箭头、圆点足以提供层次。
- 长名称使用省略号；原文可在详情展开或复制。IP、文件路径、错误详情不能永久丢失于截断。
- 输入框使用终端单元计算可见片段和光标位置，长输入应横向滚动。
- 标签和帮助文字使用一致的弹窗背景，避免在浅一阶面板上留下深色文字底块。
- 弹窗与搜索接管字符输入；关闭后把焦点还给原来选择，不把未消费的释放事件当成第二次业务操作。
- 搜索、保存和取消的语义先定清楚。推荐搜索即时过滤、Enter 确认、Esc 恢复进入前的查询；列表中的 Esc 可以清空查询。

## 4. 框架落地

### Python curses

- 使用语义 color pair 和 `bkgd` 填充应用底色；探测颜色数量，提供 16 色或反显回退。
- 封装限宽写入、显示宽度、填充、边框与按钮，统一处理中文和窗口边界。不要在最后一个单元写入后误判 curses 的边界异常。
- `get_wch()` 处理 Unicode 输入；区分输入模式和全局快捷键。为 Esc、Ctrl+U、Home/End、Delete 等提供明确处理。
- 主线程负责绘制和用户设置更新。耗时任务通过队列交回结果；退出时通过 `curses.wrapper` 恢复终端模式。
- 接管 SSH 等交互子进程前保存并退出当前终端绘制模式，返回后恢复。单独检查 Ctrl+C 和异常退出。
- 捕获 resize 后按当前窗口尺寸重新计算布局；过小的窗口给出简短提示和退出方式。

### Textual 或其他组件框架

- 优先使用框架原生的布局、主题变量、输入、焦点、Modal、列表与后台任务组件。
- 采用现有框架的 Unicode 计宽能力，避免混用手工字符坐标和组件尺寸造成偏移。
- 使用框架测试工具验证交互，并补充真实终端冒烟验证。不要为统一风格重写框架已有的输入与焦点系统。

## 5. 检查场景

按应用实际能力选取有意义的场景：

| 场景 | 检查点 |
| --- | --- |
| 128×36 宽窗口 | 分栏、信息层次、长名称、主操作 |
| 100×32 中等窗口 | 上下布局、弹窗、滚动和提示 |
| 80×24 紧凑窗口 | 主要内容与退出可用、次要信息折叠 |
| 动态缩放 | 焦点、选择与查询保留，边框不重叠 |
| 中文输入与修改 | 输入、删除、左右移动、组合字符的支持边界 |
| 搜索无结果 | 无匹配提示、清空或取消后能恢复 |
| 刷新失败 | 缓存明确标记；不误显示实时在线或成功 |
| 设置保存与取消 | 保留既有设置，取消没有写入 |
| 鼠标按钮与滚轮 | 选择与键盘一致，业务动作不重复触发 |
| 退出与子进程返回 | 终端回显、光标、鼠标模式恢复 |

截图用于视觉检查；PTY 用于输入与模式验证；状态和数据测试用于行为检查。三者的验证范围不同，交付时说明实际完成的部分。
